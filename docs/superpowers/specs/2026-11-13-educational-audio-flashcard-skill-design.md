# 教學用有聲字卡網站 Skill 設計

## 目的

建立一個可放在 GitHub、可安裝到 Codex 或 Claude Code 的跨代理 skill。學員只需提供文本、圖片素材、語音來源網站與教學目標，agent 便能自動完成資料整理、圖片處理、語音資產整理、網站製作、測試與部署準備。

## 參考案例

Skill 的說明文件使用以下已發布網站作為主要實際案例，協助學員理解輸入素材如何轉成教學網站：

<https://luanqun-bunun-animal-flashcards.netlify.app/index.html>

對應的冒險地圖與測驗頁為：

<https://luanqun-bunun-animal-flashcards.netlify.app/quiz>

此案例可參考的部分包括：

- 以 10 種動物作為巒群布農語單字與例句教材。
- 閃卡頁顯示動物圖片、族語單字、族語例句與播放按鈕。
- 提供族語單字與例句的自動播放，以及上一張、下一張操作。
- 將閃卡學習與冒險地圖、五個測驗關卡分成不同頁面。
- 使用角色選擇、地圖節點、聽音選圖、看圖選詞、看例句選圖與拼圖等互動。
- 在網站底部保留製作單位與族語語音來源。

這個網址只作為教學案例與資訊架構參考。新專案必須建立獨立的網站目錄與部署專案，不得把新網站寫入、同步或依賴「蝸牛－布農族飲食故事繪本」網站；除非使用者另外授權，也不能修改該網站。

## 目標

- 讓沒有網頁開發經驗的學員也能用原始教材產生學習網站。
- 將目前「有聲字卡＋冒險地圖＋分關測驗」的製作經驗整理成可重複使用流程。
- 同時支援 Codex 與 Claude Code 可讀取的標準 skill 結構。
- 用腳本固定容易出錯的工作：檔案掃描、圖片裁切、音檔命名、資產檢查與測試。
- 保留 agent 對教材類型、頁面功能與互動設計的判斷能力。

## 非目標

- 不把目前巒群布農語動物網站硬編碼成唯一模板。
- 不要求學員預先知道音檔檔名、資料夾結構或圖片裁切尺寸。
- 不自動修改原始教材或覆寫原始圖片。
- 不在沒有授權的情況下自動登入、上傳私人資料或發布公開網站。
- 不自行猜測不確定的族語拼寫、翻譯、方言或圖片對應。

## 方案與取捨

### 方案一：純 SKILL.md

由 agent 自行完成所有工作，檔案最少、跨工具最容易，但圖片和音檔處理容易因執行者不同而產生差異。

### 方案二：SKILL.md＋可攜式腳本（採用）

SKILL.md 負責需求理解、決策、素材核對、網站設計與權限邊界；腳本負責可機械化且容易重複的工作，例如掃描素材、建立資產清單、產生裁切版本、檢查引用與執行網站測試。

此方案在穩定性與彈性之間最平衡，也不依賴特定 IDE 或雲端平台。

### 方案三：SKILL.md＋完整網站模板

輸出一致且製作速度快，但會限制不同教材主題的版面與互動方式，不適合作為通用教學網站 skill 的第一版。

## 使用者輸入

使用者通常只需提供：

1. 文本或文件，例如 DOCX、TXT、Markdown、CSV 或貼上的文字。
2. 一組圖片或圖片資料夾。
3. 指定的語音合成網站，或明確說明使用哪個語音來源。
4. 教學目標與希望的互動功能。
5. 是否需要公開發布，以及指定的部署平台。

Agent 必須先掃描可用資料，再列出讀到的內容、缺少的資料與不確定處；不能把檔名格式、音檔命名或第二套圖片當成使用者的前置責任。

## Agent 自動處理範圍

1. 讀取文本並建立結構化資料表。
2. 保留原始語言拼寫、翻譯與來源脈絡。
3. 掃描圖片並建立圖片與詞條的候選對應。
4. 從原始圖卡產生學習頁需要的裁切圖片，保留原始圖片不變。
5. 依指定來源產生或整理單字與例句音檔；不能把未取得的音檔假裝成已完成。
6. 建立清楚的專案目錄與資產索引。
7. 依教材目標建立閃卡、播放、測驗、闖關或其他互動功能。
8. 產生桌面、平板與手機版面。
9. 執行資產、功能、響應式與瀏覽器測試。
10. 依使用者授權進行部署，並回報公開網址與驗證結果。

## 預設網站流程

```text
接收教材與目標
  ↓
掃描文件、圖片與既有專案
  ↓
建立內容資料表與不確定事項
  ↓
確認頁面與互動設計
  ↓
整理音檔與圖片資產
  ↓
建立網站與學習互動
  ↓
執行資產、功能與響應式測試
  ↓
修正測試失敗
  ↓
取得部署授權後發布
  ↓
驗證網址與回報成果
```

## 第一版腳本範圍

腳本以 Python 或 Node.js 撰寫，避免依賴 Codex 或 Claude Code 的特定 API。第一版包含：

- `scan_assets`：掃描文件、圖片與音檔，輸出資產清單。
- `build_manifest`：將人工確認後的內容資料轉成網站可讀的 JSON。
- `crop_card_images`：依設定或人工確認的裁切區域產生測驗用圖片，絕不覆寫原圖。
- `validate_assets`：檢查圖片、音檔、資料引用與檔案路徑。
- `run_site_checks`：執行 HTML、JavaScript、連結、資產與基本互動測試。

語音合成網站若沒有可公開使用的 API，agent 必須使用可授權的瀏覽器或人工確認流程取得音檔；腳本只負責下載後的整理與檢查，不假設能繞過網站限制。

## 權限與安全邊界

- 讀取使用者本機教材屬於任務範圍，但上傳到第三方網站前要確認目的與資料範圍。
- 公開部署、登入授權、上傳素材與傳送含個人資料的文本，必須在實際動作前取得使用者同意。
- 不在輸出或日誌中暴露密碼、API key、存取 token、私密網址或個人敏感資料。
- 預設先產生本機可驗證成果；只有使用者要求或確認後才部署。

## 成功條件

- skill 能被 GitHub 下載並放入 Codex 或 Claude Code 的 skill 目錄。
- agent 能從一般教材文字開始工作，不要求使用者預先設計音檔與圖片資料夾。
- 原始語言資料不被無聲改寫，疑義會被列出。
- 生成網站的資產引用完整，手機與電腦不破版。
- 測試失敗時，agent 會修正並重新驗證，而不是直接宣稱完成。
- 部署結果會明確區分「本機完成」、「已取得授權但部署失敗」與「公開網址已驗證」。
- skill 說明文件能用巒群布農語動物閃卡網站作為可理解的案例，但不會讓 agent 誤以為新專案應該併入其他既有網站。
